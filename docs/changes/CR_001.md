# CR-001: Dynamic Fuel-Caution Threshold

**Application:** Aircraft Fuel and Range Management (AFRM)  
**Original baseline:** `a2-baseline-v1.0.0`  
**Change type:** Functional algorithm enhancement  
**Status:** Proposed for controlled implementation  
**Origin:** Assignment 2 design review and baseline characterisation

## 1. Existing Behaviour

The original AFRM application uses a fixed caution threshold of 50 kg.

Fuel status is classified as:

- INSUFFICIENT when fuel margin is below 0 kg.
- CAUTION when fuel margin is at least 0 kg but below 50 kg.
- SUFFICIENT when fuel margin is at least 50 kg.

The existing implementation satisfies its original specification. However, the caution threshold does not vary with the calculated fuel requirement.

## 2. Proposed Modification

Introduce a dynamically calculated caution threshold:

\[
T_{\text{caution}}=\max(50,\ 0.10F_{\text{required}})
\]

The effective threshold will be the greater of 50 kg or 10% of total required fuel.

The existing fuel-requirement calculation and INSUFFICIENT classification boundary will remain unchanged.

The 10% caution factor is a fictional simulation parameter, independent of the existing 10% trip-fuel contingency. It is not an aviation regulatory requirement.

## 3. Requirements Impact

**FR08, revised:** Classify fuel status using fuel margin and the effective caution threshold.

**FR10, extended:** Display the effective caution threshold to explain the classification.

**FR11, new:** Calculate the effective caution threshold using the configured minimum threshold and caution percentage of total required fuel.

Existing fuel-calculation requirements FR03–FR07 and FR09 must retain their established behaviour.

## 4. Implementation Impact

Expected affected files:

- `include/afrm/flight_data.h`
- `include/afrm/fuel_status.h`
- `src/fuel_status.cpp`
- `src/main.cpp`
- `tests/test_status.cpp`
- `CMakeLists.txt`, if test registration changes are necessary
- Updated requirements, design and README

The existing `classifyFuelStatus()` interface should be retained where practical.

## 5. Expected Behavioural Change

For flight A2-DYN-LOW:

| Output | Original | Proposed |
|---|---|---|
| Required fuel | 550 kg | 550 kg |
| Fuel margin | 54 kg | 54 kg |
| Caution threshold | 50 kg | 55 kg |
| Classification | SUFFICIENT | CAUTION |

The original six-flight dataset is expected to retain its existing classifications.

## 6. Risks and Limitations

Potential risks include incorrect threshold calculation, numerical overflow, invalid policy parameters, incorrect boundary comparisons and unintended regressions.

The revised algorithm may classify additional flights as CAUTION. This is intended under the simulated policy but does not establish that the application is operationally safer.

The additional 10% caution allowance must not be confused with the existing contingency fuel calculation.

## 7. Verification and Acceptance Criteria

The change can be accepted when:

1. The effective threshold equals the greater of the configured minimum and configured percentage of total required fuel.
2. All newly defined threshold boundaries produce the expected classifications.
3. Invalid and non-finite policy values are rejected.
4. Existing fuel calculations remain unchanged.
5. Negative fuel margins continue to produce INSUFFICIENT.
6. The complete application uses and displays the effective threshold.
7. New dynamic-threshold tests pass.
8. Applicable regression tests pass.
9. Changes undergo a documented software review.
10. The revised version is identifiable through Git configuration control.

## 8. Change Control

The original baseline must remain unchanged.

Implementation will occur on a dedicated change branch, with source modifications, tests, documentation updates and review results recorded through Git.

Final acceptance and the updated baseline tag will occur only after verification and review are complete.
